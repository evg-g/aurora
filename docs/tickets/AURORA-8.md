# AURORA-8: Appointments page: tabs, day groups and a clinic filter

## Story

As a clinician, admin or patient, I want the Appointments page split into tabs and grouped by day,
so that I can see what is next and what needs action without reading one long list.

Today the page (`appointments-web/src/features/appointments/AppointmentList.tsx`) is one table,
newest first, that mixes upcoming, past, cancelled and no-show bookings. The API filters nothing
(`GET /api/v1/appointments` takes only `limit` and `cursor`), so the tabs are worked out in the
browser from the loaded appointments. No API change.

"Started" means the appointment's start time is now or earlier.

## Acceptance criteria

1. The Upcoming tab lists REQUESTED and CONFIRMED appointments that have not started, soonest first.
2. The Needs action tab lists REQUESTED appointments that have not started and CONFIRMED appointments that have started, soonest first.
3. The Past tab lists COMPLETED and NO_SHOW appointments and REQUESTED or CONFIRMED appointments that have started, newest first.
4. The Cancelled tab lists CANCELLED appointments, newest first.
5. Clinicians and admins see all four tabs. Patients see Upcoming, Past and Cancelled, and no Needs action tab.
6. Upcoming is open by default. The open tab is in the URL (`?tab=`), so a tab can be linked and stays open after a reload.
7. Each tab label shows how many appointments it holds, for example "Upcoming (12)".
8. A tab with no appointments shows its own empty message, for example "No upcoming appointments", with a Book appointment action. When there are no appointments at all, the page keeps its current "No appointments yet" state.
9. Inside a tab, appointments are grouped under one heading per day, in the clinic's time zone: "Today · Tue, Oct 6", "Tomorrow · Wed, Oct 7", otherwise "Thu, Oct 8". The year is shown when it is not the current year.
10. Each row shows the time with the clinic's zone (for example "10:00 AM PDT") as a link to the appointment, the clinic, and the status.
11. A clinic filter ("All clinics" or one clinic) limits every tab to that clinic, and the tab counts follow it. The chosen clinic is in the URL (`?clinic=`) and stays after a reload.
12. The tabs can be used with a keyboard and a screen reader: tab roles, the selected tab announced, and the arrow keys move between tabs.
13. "Load more" still loads older appointments, and they join the right tabs.
